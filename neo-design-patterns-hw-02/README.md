# ДЗ-2 до теми "Принципи проєктування SOLID"

## Звiт по роботi:

У цьому проєкті було проведено рефакторинг системи повідомлень відповідно до принципів SOLID. Спочатку клас `User` сам створював `NotificationService` і викликав надсилання, сам сервіс мав окремий метод під кожен канал (`sendEmail`, `sendSMS`, `sendPush`) і напряму створював `Logger` через `new` — тому додати новий канал чи підмінити логер без правок старого коду було неможливо.

### Реалізовано:

- SRP — `User` тепер лише зберігає дані користувача; надсилання винесено в окремі класи-канали, логування — у `Logger`, координація — у `NotificationService`. Кожен клас відповідає за одну задачу;
- OCP — щоб додати новий канал (наприклад, Telegram), достатньо створити новий клас-канал і передати його в `NotificationService` — існуючий код чіпати не треба;
- LSP — `EmailNotification`, `SMSNotification`, `PushNotification` реалізують один спільний інтерфейс і повністю взаємозамінні;
- ISP — інтерфейси розділені за відповідальністю: окремо `ILogger` для логування, окремо `INotificationChannel` для каналу сповіщень;
- DIP — `NotificationService` і кожен канал не створюють свої залежності самі, а отримують їх ззовні через конструктор (логер і список каналів передаються, а не створюються всередині).

### Канали повідомлень:

- EmailNotification
- SMSNotification
- PushNotification

## Запуск проєкту

```bash
npx ts-node src/main.ts
```
